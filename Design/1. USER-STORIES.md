## Central Authority

### Identity Management
- As the central authority, I want to be able to create new Digital IDs `so that` I can register citizens in the system
- As the central authority, I want to be able to alter the status of a Digital ID (active, suspended, or revoked) `so that` I can specify which Digital IDs can be queried by other organisations
- As the central authority, I want mutable attributes to be readable and modifiable `so that` the Digital ID can be kept up to date
- As the central authority, I want immutable attributes to be readable, but not modifiable `so that` core attributes cannot be modified, better reflecting the real world

### System Behaviour
- As the central authority, I want the system to reject requests to revoked or non-existent Digital IDs `so that` revoked Digital IDs have their states preserved and do not have unintended modifications
- As the central authority, I want the system to reject requests using a deterministic approach `so that` the system behaves in a consistent and predictable manner

### Auditing
- As the central authority, I want to view and filter a persistent log of all requests (accepted and rejected) on the system `so that` I can easily track changes
- As the central authority, I want the persistent log to include reasoning behind the changes `so that` the system complies with the Data Protection Act by documenting the justification for storing and modifying personal data

### Capabilities
- As the central authority, I want to be able to search or filter Digital IDs by attribute values `so that` I can locate specific citizens without knowing their Digital ID

## Other Organisations

### System Behaviour
- As an organisation, I want the system to reject requests that exceed my authorisation level `so that` only permitted operations can be performed
- As an organisation, I want to be able to receive clear error messages if a request is rejected `so that` I can take action to resolve the issue

### Capabilities
- As an organisation, I want to be able to check if a Digital ID exists `so that` I can confirm a Digital ID exists before querying data
- As an organisation, I want to be able to check the status of a Digital ID `so that` I can see if it is valid before querying attribute data
- As an organisation, I want to be able to access only the attributes of Digital IDs which I need `so that` I am complying with the Data Protection Act by not storing information I do not need
